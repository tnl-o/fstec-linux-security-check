# FSTEC Linux Security Check

Автоматизированный скрипт для проверки соответствия операционной системы Linux рекомендациям ФСТЭК России по безопасной настройке.

## 📋 Описание

Скрипт `fstec_linux_security_check.sh` выполняет комплексную проверку системы на соответствие требованиям методического документа:

**"РЕКОМЕНДАЦИИ ПО БЕЗОПАСНОЙ НАСТРОЙКЕ ОПЕРАЦИОННЫХ СИСТЕМ LINUX"**

Федеральной службы по техническому и экспортному контролю (ФСТЭК России)

- **Официальный документ**: [Методический документ ФСТЭК](https://fstec.ru/documents/tekhnicheskaya-zashchita-informatsii/metodicheskie-dokumenty/751)
- **Дата утверждения**: 25 декабря 2022 г.

## ✨ Особенности

- ✅ **Полное покрытие рекомендаций ФСТЭК** (разделы 2.1 - 2.6)
- 🎨 **Цветовая подсветка результатов**:
  - 🟢 Зелёный — проверка пройдена успешно
  - 🔴 Красный — обнаружены нарушения
  - 🟡 Жёлтый — предупреждения и рекомендации
- 📝 **Детальные рекомендации** по устранению найденных проблем
- 🔍 **Расширенный аудит** дополнительных параметров безопасности
- 🛡️ **Только чтение** — скрипт не вносит изменений в систему

## 📦 Что проверяется

### 2.1. Настройка авторизации
- Проверка учётных записей с пустыми паролями
- Отключение входа root по SSH

### 2.2. Ограничение механизмов получения привилегий
- Ограничение доступа к команде `su`
- Анализ конфигурации `sudo` и `/etc/sudoers`

### 2.3. Права доступа к объектам файловой системы
- Права на системные файлы (`/etc/passwd`, `/etc/group`, `/etc/shadow`)
- Права на исполняемые файлы и библиотеки
- Права на файлы заданий cron
- Права на SUID/SGID-приложения
- Права на домашние директории пользователей
- Права на файлы истории и настройки оболочек

### 2.4. Настройка механизмов защиты ядра Linux
- `kernel.dmesg_restrict`
- `kernel.kptr_restrict`
- `init_on_alloc`, `slab_nomerge`
- Настройки IOMMU
- `randomize_kstack_offset`
- `mitigations=auto,nosmt`
- `net.core.bpf_jit_harden`

### 2.5. Уменьшение периметра атаки ядра Linux
- Отключение `vsyscall`
- `kernel.perf_event_paranoid`
- Отключение `debugfs`
- `kernel.kexec_load_disabled`
- `user.max_user_namespaces`
- `kernel.unprivileged_bpf_disabled`
- `vm.unprivileged_userfaultfd`
- `dev.tty.ldisc_autoload`
- Отключение TSX
- `vm.mmap_min_addr`
- `kernel.randomize_va_space`

### 2.6. Настройка средств защиты пользовательского пространства
- `kernel.yama.ptrace_scope`
- `fs.protected_symlinks`
- `fs.protected_hardlinks`
- `fs.protected_fifos`
- `fs.protected_regular`
- `fs.suid_dumpable`

### Расширенные проверки
- Анализ файлов в `/etc/sudoers.d`
- White-list аудит SUID/SGID-приложений
- Проверка PAM (политика паролей, лимиты входов)
- Проверка SELinux/AppArmor
- Аудит `limits.conf`
- Расширенный аудит `sshd_config`
- Проверка статуса небезопасных сервисов

## 🚀 Установка и использование

### Требования

- Bash 4.0+
- Права root (рекомендуется для полной проверки)
- Linux-система (Debian, Ubuntu, CentOS, RHEL и др.)

### Быстрый старт

📌 **Нужна краткая инструкция?** См. [QUICKSTART.md](QUICKSTART.md)

1. **Клонируйте репозиторий**:
```bash
git clone https://github.com/yourusername/fstec-linux-security-check.git
cd fstec-linux-security-check
```

2. **Сделайте скрипт исполняемым**:
```bash
chmod +x fstec_linux_security_check.sh
```

3. **Запустите проверку** (с правами root):
```bash
sudo ./fstec_linux_security_check.sh
```

Или укажите полный путь:
```bash
sudo /path/to/fstec_linux_security_check.sh
```

## 📖 Интерпретация результатов

- **[OK]** — проверка пройдена, система соответствует требованиям
- **[FAIL]** — обнаружено нарушение требований ФСТЭК
- **[WARN]** — потенциальная проблема или предупреждение
- **[N/A]** — проверка не применима к данной системе
- **[РЕКОМЕНДАЦИЯ]** — конкретные действия для устранения проблемы

## 🔧 Устранение проблем

Для каждого найденного нарушения скрипт выводит рекомендации по устранению. Примеры:

- **Права доступа**: `chmod 640 /etc/shadow && chown root:shadow /etc/shadow`
- **Параметры ядра**: добавление опций в `/etc/default/grub` и выполнение `update-grub`
- **Sysctl параметры**: добавление в `/etc/sysctl.conf` и применение через `sysctl -p`

⚠️ **Важно**: Перед применением изменений рекомендуется протестировать их на тестовой системе.
